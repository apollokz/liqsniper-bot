# LiqSniper HFT Simulation Bot (v1.8.0) — Внутреннее Техническое Руководство

Данный документ содержит детальное архитектурное описание высокочастотного симуляционного торгового робота LiqSniper (v1.8.0), развернутого в среде `~/liqsniper-bot` на VPS Contabo (Германия).

---

## 1. Архитектура и Конвейер Данных (Data Pipeline)

Архитектура системы построена на асинхронном многопоточном сборе данных с параллельной валидацией через разделяемую память `GlobalState`. Потокобезопасность обеспечивается за счёт `sync.RWMutex`.

             ┌──────────────────────────────────────┐
              │              GlobalState             │
              │ (Mutex R/W, Strike, CLOB, Oracle)    │
              └──────────────────┬───────────────────┘
                                 │
     ┌───────────────────────────┼───────────────────────────┐
     ▼                           ▼                           ▼

┌─────────────────┐ ┌─────────────────┐ ┌─────────────────┐ │ DataEngine │ │ RTDSEngine │ │ BinanceStreams │ │ (Polygon RPC) │ │ (Chainlink WS) │ │ (Combined WS) │ └─────────────────┘ └─────────────────┘ └─────────────────┘

### Компоненты сбора данных:
1. **DataEngine (`engine_onchain.go`)**: 
   * Опрашивает RPC-ноду сети Polygon каждые 2 секунды.
   * Получает метку времени последнего блока для синхронизации локального времени с ончейн-временем.
   * Реализована защита от пустых ответов и тайм-аутов RPC (аномалия заморозки таймера полностью устранена).
2. **RTDSEngine (`ws_rtds.go`)**:
   * Подключается к Real-Time Data Service (RTDS) Polymarket.
   * Парсит поток оракула Chainlink (`btc/usd`) для расчета цены страйка и накопления тиковой истории в кольцевом буфере `Ticks`.
   * Содержит резервный фоллбек-канал `crypto_prices` для обновления Binance в случае обрыва прямого соединения.
3. **BinanceStreams (`binance_ws.go`)**:
   * Подключается к мультиплексированному потоку Binance Futures `wss://fstream.binance.com/stream`.
   * Каналы подписки приведены к **строгому нижнему регистру** во избежание сбоев парсинга со стороны API: `btcusdt@aggtrade`, `ethusdt@aggtrade`, `btcusdt@forceorder`, `btcusdt@depth20@100ms`.
   * Обеспечивает прямую трансляцию котировок Binance с фиксацией времени жизни пакетов (`BinanceLastUpdate`).
4. **WebSocketEngine (`websocket.go`)**:
   * Каждые 5 минут находит активный бинарный рынок на Polymarket через Gamma API.
   * Подписывается на CLOB WebSocket Polymarket для получения лучших цен заявок по токенам (`best_bid_ask`).

## 2. Математическая Формализация Торговых Сетапов

Оценка рынка и генерация сигналов происходят в сверхбыстром цикле `StartEvaluationLoop` каждые **100 миллисекунд**. Сигналы отправляются при строгом соблюдении временного фильтра (90-180 секунд до экспирации) и дистанции до страйка ($\le \$80$).

### Сетап 1: Latency Arbitrage (MM Latency & Lag)
Эксплуатирует задержку обновления котировок маркет-мейкеров Polymarket относительно спота Binance.
* **Триггер**: Изменение цены BTC на фьючерсах Binance на величину $\ge 0.015\%$ за интервал в 100 миллисекунд.
* **Формула**:
  $$\text{Velocity} = \frac{P_{now} - P_{100ms}}{P_{100ms}} \times 100$$
* **Исполнение**: Покупка акций в сторону импульса при обесцененном стакане ($0.05 - $0.15).

### Сетап 2: Limit Order Absorption
Определяет истинное торможение цены об плотную лимитную плиту (Bid/Ask Wall) крупного игрока.
* **Триггер**: Кумулятивная дельта объемов ($CVD_{15s}$) превышает критический порог, а дисбаланс стакана ($OBI$) демонстрирует сильное сопротивление.
* **Формула CVD**:
  $$\text{CVD}_{15s} = \sum (\text{Volume} \times (1 \text{ if buy else } -1))$$
  *где покупка/продажа определяется по флагу агрессора `IsBuyerMM`.*
* **Формула OBI (на глубине 0.5%)**:
  $$OBI = \frac{\sum Vol_{Bid} - \sum Vol_{Ask}}{\sum Vol_{Bid} + \sum Vol_{Ask}}$$
* **Условие**: При $CVD_{15s} < -5$ BTC (продажи) и $OBI > 0.55$ (плотная стена Bid) генерируется сигнал **UP**.

### Сетап 3: Stop Run Liquidity Sweep
Ловит резкий вынос стоп-лоссов ритейл-трейдеров за пределами 5-минутных экстремумов.
* **Триггер**: Скачок тиковой интенсивности транзакций ($I_{tick}$) в 2.5 раза выше скользящей средней за 30 секунд ($SMA_{30s}$) в момент ложного пробоя high/low.
* **Условие**:
  $$I_{tick} > 2.5 \times I_{avg} \quad \text{and} \quad P_{now} < \text{Low}_{5m} \quad \text{and} \quad \text{CVD}_{15s} > 0$$

### Сетап 4: Cross-Asset ETH Lead
Использует закон опережения Ethereum (ETH) как более «тонкого» актива по отношению к плотному BTC во время импульсных фаз.
* **Триггер**: Рост базиса ETH/BTC свыше 0.15% при зажатом в рендже BTC.
* **Формула**:
  $$\text{Delta}_{ETH} = \frac{P_{ETH} - P_{BTC}}{P_{BTC}} \times 100$$
* Положительное отклонение $\ge 0.15\%$ генерирует опережающий сигнал **UP** для биткоин-контракта.

## 3. Модуль Симуляции (Paper Trading Engine)

Симулятор (`simulator.go`) работает асинхронно и полностью воспроизводит боевую среду:
* **Учет Taker-комиссии Polymarket**: С каждой симуляционной сделки вычитается актуальная комиссия за транзакцию в размере **7.2 bps (0.00072$)** согласно Red Teaming аудиту.
* **Валидация экспирации**: В момент наступления экспирации контракта (`now >= ExpiryTime`) планировщик сверяет финальную цену оракула с ценой страйка, рассчитывает чистый профит/убыток и фиксирует результат.
* **Защита от спама**: Встроена блокировка, запрещающая открытие более 1 сделки по конкретному типу сетапа в рамках одного 5-минутного интервала.

## 4. Веб-Интерфейс Админки (v1.8.0)

Админка запускается в фоновом горутин-потоке на порту **`39182`** и имеет модульную структуру:
* **API Статус (`/api/status`)**: Возвращает структурированный JSON-пакет, содержащий текущее время блокчейна, страйк, цену спота/фьючерса, стакан и полный слайс открытых/закрытых сделок.
* **HTML/JS Интерфейс (`admin.go`)**: Веб-страница на базе чистого CSS/JS. Автоматически опрашивает API раз в 1 секунду, динамически обновляя дашборды и таблицу позиций без перезагрузки страницы.

## 5. Администрирование и Дебаг

### Управление службой через Systemd:
* Перезапуск: `systemctl restart btc_pro`
* Остановка: `systemctl stop btc_pro`
* Статус службы: `systemctl status btc_pro`

### Мониторинг логов в реальном времени:
Для просмотра live-логов компилятора, оракула Polymarket и срабатывания сетапов симулятора используйте:
`journalctl -u btc_pro -f -n 100`
